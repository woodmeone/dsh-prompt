## 四、怎么用

### 4.1 安装

```bash
# 在 profiles/web 的 package.json 的 dsh.profile.bundles 里加：
"dsh-prompt"

# 或在 dsh 里
dsh plugin install D:\Project\Test\purge-deploy\dsh-prompt
```

### 4.2 施加尾部注入补丁

打开右下角 dock → 「提示词」tab → 状态栏会显示 **「装宿主补丁」** 按钮（没装时）。

点它一次。这条补丁改写宿主的 `dsh-agent-loop/lib/index.js`，
让尾部块接进本轮请求。

- 会自动留一份 `.dsh-prompt.bak` 备份
- **需要重启 dsh** 才完全生效
- 回滚：`npm run patch:rollback`

不装补丁时：顶部注入照常工作，尾部只能看装配结果（不进请求）。

### 4.3 面板操作

| 动作 | 操作 |
|---|---|
| 换位置 | 顶部 / 尾部两个 tab |
| 排序 | 按住 ⠿ 拖到目标行，松手 |
| 开关 | 点勾选框 |
| 改正文 | 点「编辑」→ 改 → 「保存」 |
| 回出厂正文 | 点「还原」（只对改过的块可见） |
| 删块 | 点「删除」（默认块没有这个按钮） |
| 一块两挂 | 编辑器里点「同时挂到另一位置」 |
| 新建 | 底部输 id + 名字 → 「新建到「顶部/尾部」」 |
| 全量重置 | 头部「恢复出厂」 |

## 五、⚠ 与 dsh-purge 共存

两个插件都注册 `systemPrompt.section`，都会往 `-100000` 放主段。

| 你的意图 | 操作 |
|---|---|
| 两个都用 | **不用改**。两个段并列，各自生效 |
| 只用 dsh-prompt 管提示词 | 改 purge 自己的配置关掉提示词层（注意 purge 的 `enabled` 是总闸，关掉 46 个补丁一起没） |
| 只留 purge | 在 dsh-prompt 的 `cordis.patch.yml` 里 `enabled: false` |

**本插件不删、不改 purge 的任何文件。**

## 六、现场状态说明（重要）

调查时发现宿主上有一处**遗留问题**，已在本插件内做了检测上报：

```
宿主 @deepseek-ai/dsh-agent-loop 等 29 个包带着 [dsh-loom] 补丁标记
但 dsh-loom 插件在 cordis.patch.yml 里是 disabled，且不在 bundles 列表
→ globalThis.__dshPurgeHungPrompt 从没被注册过
→ 宿主那条置顶补丁永远取到 null，注入链在宿主层空转
```

**这是「上一版效果特别差」的现场根因之一**：补丁与插件生命周期解耦。

**dsh-prompt 的应对**：
1. 自己的补丁用独立标记 `[dsh-prompt]`，与 `[dsh-purge]` / `[dsh-loom]` 可分辨
2. 面板状态栏会显示「宿主持有外来补丁：dsh-loom」——**不擅自删别人的补丁**
3. 尾部注入**不依赖任何 globalThis 钩子存活**：钩子缺失时 fail-open，请求按原样发出

## 七、抗截断层

尾部注入的最大价值不是「再强调一遍规则」，是**抗截断**：

- 模型**愿意写但写一半停** = 效果等同拒绝（社区常忽略的第六类）
- 尾部那块在**离生成点最近的位置**，是唯一能直接干预「要不要继续写」的槽
- 出厂块 `core-tail`（尾部续压）就是为这个准备的

想更进一步，可以在尾部加「起笔锁」类块：命令模型**第一个输出 token 必须是 X**。
